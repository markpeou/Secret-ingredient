# The Secret Ingredient

A mobile-first icebreaker. Players answer 10 casual questions and get a **signature dish** from around the world, plus a personalised **spice blend** made only from that dish's real spices (3–6 spices, percentages always totalling exactly 100%).

Visual style: a bright, chunky cooking-game look (gingham tablecloth, thick outlines, bouncy buttons, a lifted cloche and a "Signature dish" stamp). The host is Pipi, an original kawaii chef with 13 expressions who reacts to every answer. All 26 spices are drawn as kawaii characters, and the result is a two-sided collectible card players can flip, save and share. It's inspired by cooking games and trading cards but uses no characters, names, logos or artwork from any existing game.

No accounts, backend, API keys, build step or dependencies. Answers live only in memory and are never stored.

## Run it

```bash
# 1. Just open it
open index.html            # or double-click it

# 2. Serve locally (recommended, so fonts and clipboard behave like production)
python3 -m http.server 8000
# then visit http://localhost:8000

# 3. Single file
node scripts/bundle.mjs    # writes dist/secret-ingredient.html, one self-contained file
```

To try it on your phone, serve it with option 2 and open `http://<your-computer's-LAN-IP>:8000` on the same Wi-Fi.

## Test it

```bash
npm test                 # engine unit tests (Node 18+, no installs)
npm run simulate         # distribution report over 6,000 simulated players

# Browser flow test (needs: pip install playwright && playwright install chromium)
python3 -m http.server 8000 &
python3 tests/e2e.py http://localhost:8000/index.html [screenshot-folder]
```

The unit tests check, among other things, that **every blend only contains spices from its dish**, percentages always total 100, every dish turns up for 1–8% of players, results are deterministic, and extreme players are led by a spice that matches them.

The e2e test validates every illustration, prints a card for all 31 dishes, then plays seven full sessions on a 390 × 720 phone viewport (mouse and keyboard). It checks the dock and every answer option are on screen without scrolling, answers auto-advance, Back keeps answers, the food theme stays hidden until the reveal, the dish only appears after the blend, the question card hugs its options, the card flips, saves each side and shares both, copy works, restart fully resets, there is no sideways scrolling, and reduced-motion mode works.

## How the scoring works

It's a playful, transparent interpretation, not a psychological test. The full map of every spice and dish is in `docs/recipe-book.md`.

1. **Answers → traits.** Every answer option carries weights (1–3) across nine hidden traits: explore, energy, steady, warmth, space, observe, drive, flow, play. For each trait, the engine compares what the player picked with what was on offer in the questions they saw, so the random question selection doesn't skew results.
2. **Traits → spice affinities.** Each spice expresses a few traits (Cinnamon is warmth, Sichuan pepper is novelty, Cumin is steadiness, and so on). A player's affinity for a spice is measured against how a typical player scores it (`SPICE_NORMS`), so spices that are easy to score highly don't dominate.
3. **Spice affinities → dish.** Every dish lists its real spices with rough proportions: Phở is star anise, cinnamon, coriander seed, ginger, cloves and cardamom; lasagne is nutmeg, black pepper and fennel. The dish whose spice set lines up best with the player's affinities wins, plus a small capped calibration offset (`DISH_BIAS`) that keeps every dish reachable.
4. **Dish → blend.** The blend uses **only the dish's own spices**, so Phở never comes with mustard and lasagne never comes with ginger. The dish's usual proportions are tilted towards the spices the player leans into, so two people with the same dish get different mixes.
5. **Percentages.** Up to 6 spices; each gets at least 10% and the rest is shared in 5% steps by the largest-remainder method, so the total is always exactly 100.
6. **Text.** Blend names combine the top two spices ("The {adjective of spice 2} {noun of spice 1}", for example The Old-School Showstopper). The overview uses the two strongest traits plus either a contrast or a note about the weakest one. The reveal never links a spice back to a specific answer, so the result keeps its mystery.

Results are deterministic. Tuning constants are in `SI.TUNING` at the top of `js/engine/scoring.js`.

**After editing questions, spices or dishes:** run `node scripts/calibrate.js`, then `npm test`, then `node scripts/recipe-book.js`.

## Screens and layout

The game is built as a phone-sized screen, not a long page:

- **One screen at a time:** welcome → 10 questions → transition → blend → dish → card.
- **Dock:** each screen has a bottom dock that is always visible and holds the next step (Back, Reveal my dish, My card, or the card's icon buttons and Share). Only the middle of the screen can scroll, and only when it really has to.
- **Questions:** each answered card slides off to the left and the next slides in from the right (from the left when going Back). Taps are ignored for the quarter-second a card is moving, so they always land on a still card. Picking an answer moves on automatically after Pipi reacts (about 0.75 s). There is no Next button. Back returns with the answer still selected, and tapping any option (including the selected one) carries on. Keys 1–6 choose.
- **Blend:** the spice details are a swipeable row. Tapping a slice of the gauge (or a dot) brings that spice into view.
- **Card:** the card has its own screen and sizes itself to the space between the header links and the dock.
- **Touch screens:** hover styles only apply on devices with a real pointer, so a tapped spot never looks pre-selected on the next question.
- **Short screens:** compact styles apply below 760, 720 and 660 px tall.

At 390 × 700 and taller, every screen fits without scrolling for 25 sampled results. At 390 × 640 the questions still fit, and some blend and dish screens scroll slightly with the dock still visible.

**Origin:** the dish screen shows a flag-and-country pill on the reveal. Regions that span several countries (West Africa, North Africa, the Levant) use a map pin instead of a flag. On systems that can't draw flag emoji (most Windows browsers), a map pin is used everywhere.

## Pipi's reactions

When a player picks an answer, Pipi reacts with the expression linked to that answer's strongest hidden signal: star eyes, hearts, a cheer, a calm snooze, a thinking face and so on (`REACTIONS` in `js/app.js`). The lines never name a trait ("Aww, that’s sweet.", "Hmm, interesting…"). The face system is shared: `SI.chars.face(x, y, scale, mood)` draws any of the 11 expressions onto any character.

## The collectible card

The dish screen prints a two-sided 750 × 1050 card. Tap it (or the flip button) to turn it over.

**Reveal:** the first time the card screen opens, the card sits in a wooden recipe file with a few other cards, pops out, the box drops away, and a cloche lifts off the dish in the art window. Until the player has flipped a card once, it gives a little jiggle every few seconds as a hint. That is remembered in the browser, so returning players don't see the hint again. With reduced motion, the card simply appears.

**Front**, the player's traits, laid out like a trading card in this game's style:
- "Dish – Country" (e.g. Sambar – 🇮🇳 South India; long names put the country beside the Signature dish tag), a **Heat** score (from each spice's `heat` value) and a badge for the leading spice. The frame is tinted in that spice's colour.
- Art window with Pipi and the dish, then a ribbon with the blend name.
- **Strengths:** three, one from each of the player's three strongest traits.
- **Weakness, Resists, Recharges with, Clicks with:** a 2 × 2 grid drawn from the same traits (`narrative.js`).
- **Signature move:** from the leading spice, with a spice-icon cost of 1–3.
- Flavour text, set number ("No. 24/31") and rarity stars that go up with blend size.

**Back**, the full recipe: the blend name, a slim gauge, then every spice with its share, role, plant family and what it says about the player. Shorter blends also get a "Why this dish?" panel. The flavour profile sits at the bottom.

The card dock has three icon buttons (flip, save this side, copy result) and a **Share** button.

**Share** (one action, two separate PNGs):
- Where the browser can share image files (most phones in a normal browser tab), one share sheet carries the front and the back as two images, plus the result text.
- Where sharing is blocked, for example inside the published claude.ai page, it saves both sides one after the other instead. On claude.ai each save asks the viewer to confirm, so there are two prompts. In the Claude mobile apps each save opens the phone's share sheet.
- In a desktop browser tab both PNGs download.

The save icon saves only the side you're looking at. The copy icon copies the result as text where the browser allows it.

## Accessibility

Real radio inputs, number keys 1–6 to choose (the question then moves on by itself) visible focus, focus moves to each new screen's heading, readable contrast, text alternatives for the gauge and both card sides, a keyboard-operable flip, and `prefers-reduced-motion` turns off all animation.

## Known limits

- Fonts load from Google Fonts; offline, the page and card fall back to system rounded fonts.
- Spices are whole spices only. Fresh herbs, garlic, chilli pastes and so on aren't part of any blend.
- The calibration offsets cap at ±0.6, so very common or rare dishes are evened out without overriding the answers.
